# E2Eテストケース一覧

## 1. 目的

本ドキュメントは、`CLAUDE.md` のテスト方針「E2E（Playwright）は主要フロー（ログイン → 大会/競技/選手情報登録 → 組合せ表生成 → スコア入力 → 順位表確認）のみを対象とし、全画面を網羅するものではない」に基づき、Playwrightで自動化した主要シナリオを列挙する。

- 利用者が実際に画面を操作する流れ（画面間の遷移・ダイアログ・画面への反映）を、開発サーバーに対してブラウザ操作で検証する。
- 個々のバリデーション・ブロック系ルール・API仕様・計算ロジックの網羅は目的としない（`docs/ユニットテスト.md`・`docs/結合テスト.md` を参照）。
- データ出力（Excel出力）は要件定義書5章で将来対応のため対象外とする。
- 画面ID・URL・ラベル・ボタン名は `docs/画面仕様書.md`・`docs/操作手順書.md` および実装（`src/app`・`src/components`）に準拠する。

## 2. 前提

### 2.1 テストデータの投入方針

| 区分 | 方法 | 対象 |
|---|---|---|
| 主要フロー（E2E-01〜04） | **画面操作（UI）** | 大会登録・競技情報・選手登録（「追加して続けて登録」）・組合せ表作成・スコア入力・順位表作成・手動確定・大会終了・ログアウト |
| 補助部分（E2E-05・06の前提データ） | **API**（`tests/e2e/support/seed.ts`） | 閲覧モード・バックアップ復元の確認に必要な、確認対象ではない大会・競技情報・選手・組合せ表・スコア・順位表・バックアップの用意 |

- E2E-05・06でAPIを使うのは「前提データの用意」のみで、確認対象の操作（閲覧・手動バックアップ・データ変更・復元）は画面操作で行う。
- シャッフル方式の組合せ表はランダムに生成されるため、スコアはパーティではなく**選手名で引き当てて**入力する（スコア入力ダイアログに並ぶ選手名を読み取り、サンプルデータの打数を入力する）。

### 2.2 仕様変更への対応（2026-11-19 実装済み）

本E2Eは、リリース準備中にユーザー決定により実装された以下の仕様変更を検証する。

| 記号 | 仕様変更 | 該当ステップ |
|---|---|---|
| (a) | 閲覧モード・大会終了中、A3〜A5の「組合せ表を作成する」「大会を開催する」、A3・A4の「保存」「キャンセル」は**非表示ではなく表示したままdisabled**になる（A4は「保存」のみ） | E2E-01 Step13、E2E-05 Step2〜3 |
| (b) | 大会「終了」中は「順位表作成」と手動確定も**disabled**（APIでも拒否） | E2E-01 Step13、E2E-03 Step5 |
| (c) | 選手情報は**どの項目（選手名・生年月日を含む）の変更でも**、試合結果が未入力なら確認の上で組合せ表がリセットされる | E2E-01 Step6 |

### 2.3 待機・セレクタの方針

- セレクタは `getByRole`・`getByLabel` を優先し、表の行・セルなど役割で特定できないものは実装の `data-testid`（`tournament-row`・`player-row`・`party-N`・`row-<選手名>-<ラウンド>`・`individual-row`・`team-row`・`backup-row` 等）を使う。
- 固定時間の待機（`waitForTimeout`）は使わない。保存系の操作はAPIレスポンスを待ち（`waitForResponse`）、画面の更新は `expect` の自動リトライ・`expect.poll` で待つ。

## 3. 実行方法

```bash
npm run test:e2e
```

- 設定ファイル：`playwright.e2e.config.ts`（`testDir: tests/e2e`）
- 開発サーバー（`next dev`）をポート **3200**・データ保存先 **`.e2e-data`**（`GRANDGOLF_DATA_DIR`）で自動起動する。データ保存先はテスト開始前に初期化する。
- 管理者アカウントは環境変数 `ADMIN_ID` / `ADMIN_PASSWORD`（`tests/e2e/fixtures/env.ts` の `E2E_ADMIN`）でシードする。`SESSION_SECRET` もテスト用の値を渡す。
- `workers: 1`・直列実行（E2E-06の復元は全大会のデータを上書きするため）。1テストのタイムアウトは10分（E2E-01は40名の登録と全スコア入力を画面操作で行う）。
- **注意**：結合テスト（`npm run test:integration`、ポート3100）と同じく `next dev` を使い `.next` ディレクトリを共有するため、結合テストや他の開発サーバーと**同時に実行しないこと**。
- 失敗時はトレース・スクリーンショットを `test-results/` に保存する（`npx playwright show-trace <trace.zip>` で確認）。
