# 要件定義書  
### プロジェクト名  
グランドゴルフしようよ（試合管理システム）  
  
## 1. システム概要  
  
### 1.1 背景  
グランドゴルフ大会運営において、チーム登録、試合組合せ作成、スコア入力、順位計算などをExcelで管理しているため、入力ミスや集計ミスが発生している。   
これらの業務をシステム化し、大会運営の効率化を図る。  
  
### 1.2 目的  
効率化を図るため、以下の機能を提供する。  
- 大会情報登録  
- 競技情報登録  
- 選手情報登録  
- 組合せ表生成  
- スコア表生成  
- スコア入力、計算  
- 順位表作成  
- データ出力（将来対応。5章参照）  
  
  
## 2. システム利用者  
  
### 2.1 管理者  
大会全体を管理し、以下の機能を利用可能とする。管理者アカウントは単一とし、環境変数（.env）でシードした1アカウントのみで運用する（追加の管理者アカウントを作成する機能は設けない）。  
- 大会情報登録・編集・削除  
- 競技情報登録・編集・削除  
- 選手情報登録・編集・削除  
- 試合(組合せ表、スコア表)作成  
- 試合結果(スコア入力、計算)登録  
- 順位表作成  
- データ出力（将来対応。5章参照）  
  
登録済みの大会/競技/選手情報は、登録後も編集・削除が可能とする。
ただし、試合(組合せ表、スコア表)が既に生成された後に関連する情報（競技情報・選手情報）を変更する場合、試合結果が未入力であれば、確認ダイアログで同意した時点で既存の組合せ表・スコア表を自動的に削除し、再生成が必要となる旨を管理者に確認する（選手情報は、選手の追加・削除および選手名・生年月日を含むいずれの項目の変更も対象とする）。
試合結果が1件でも登録されている場合は、組合せ表の編成に影響する項目（競技情報の全項目、選手情報のパーティ固定・パーティ番号・チーム名・不参加）の変更自体をブロックする（詳細は3.2・3.3を参照）。この場合も、組合せ表の編成に影響しない選手名・生年月日の訂正は、組合せ表・スコア表・試合結果を削除せずに行える。
同様に、試合結果が登録されている選手の削除もブロックする（詳細は3.3を参照）。  
  
大会情報を削除した場合、紐づく競技情報・選手情報・試合(組合せ表、スコア表)・試合結果は連鎖的に削除（カスケード削除）される。
削除前に確認ダイアログを表示する。  
  
大会には「進行中」「終了」のステータスがあり、登録時のデフォルトは「進行中」とする。
管理者は任意のタイミングで「大会を終了する」操作によりステータスを「終了」に切り替えることができ、また「終了」を取り消して「進行中」に戻すこともできる。
「終了」の間は、大会情報・競技情報・選手情報の編集、試合結果の入力・修正、順位表の作成および順位の手動確定（じゃんけん結果の確定）を一切行えない（閲覧のみ可能。該当する操作のボタンはUI上disabledにし、APIレベルでも拒否する）。大会情報の削除は「終了」の間も行える。  
  
### 2.2 参加者（将来対応）
参加者向けのログイン不要の閲覧機能は将来対応とする（5章参照）。今回のスコープでは「参加者」ロール・閲覧用URLは提供しない。
  
### 2.3 閲覧モード利用者  
ログイン画面に、ID・パスワードなしで入れる「閲覧モードで見る」ボタンを用意する。
閲覧モードでは、管理者向け画面を2.1と同じ範囲で閲覧できるが、登録・編集・削除・試合(組合せ表、スコア表)生成・試合結果入力・バックアップ作成・リストアなど、データを書き換える操作は一切行えない（該当する操作のボタンはUI上disabledにし、APIレベルでも拒否する）。  
  
  
## 3. 機能要件  
  
本章の各項目表で「MAX：全角n文字」と定めている項目について、上限を超える入力はエラーとして保存を拒否する（自動切り詰めは行わない）。  
  
### 3.1 大会情報登録  
### 概要  
大会情報を登録する。  
**項目**  

| 項目   | 必須 | 条件 | 登録内容                |
| ---- | -- | -- | ------------------- |
| 大会名  | ◯  |    | MAX：全角50文字、デフォルト：空白 |
| 開催日  | ◯  |    | カレンダー、デフォルト：登録日     |
| 開催場所 | ◯  |    | MAX：全角50文字、デフォルト：空白 |
  
### 条件  
- 大会のステータス（進行中/終了）の管理方法は2.1を参照。ステータスが「終了」の間は大会情報の編集を行えない  

### 例  
- 大会名：定例会  
- 開催日：yyyy/mm/dd  
- 開催場所：グラウンド  
  
### 3.2 競技情報登録  
### 概要  
競技情報を登録する。  
**項目**  

| 項目 | 必須 | 条件 | 登録内容 |
| --------------- | -- | ----------------------- | --------------------------------------------------- |
| ラウンド数 | ◯ |  | 範囲：1〜5、デフォルト：1 |
| ホールインワン時のスコア変換 | ◯ |  | チェックボックス：変換あり(チェックあり)、変換なし(チェックなし)、デフォルト：変換あり |
| ホールインワン時のスコア変換値 |  | ホールインワン時のスコア変換が、変換ありの場合 | 範囲：-5〜1、デフォルト：-2 |
| パーティの最大人数 | ◯ |  | 範囲：1〜6、デフォルト：6 |
| パーティの決定方法 | ◯ |  | 選択：チーム or シャッフル |
| チーム戦 | ◯ |  | チェックボックス：チーム戦あり(チェックあり)、チーム戦なし(チェックなし)、デフォルト：チーム戦なし |
| チーム戦の順位決定方法 |  | チーム戦が、チーム戦ありの場合 | 選択：合計 or 平均 |
  
### 条件
- 競技情報は1大会につき1件のみ登録する（BaseProjectと異なりカテゴリ単位の複数登録は行わない）
- 試合結果が1件でも登録されている場合、本画面の全項目（ラウンド数・ホールインワン時のスコア変換（値）・パーティの最大人数・パーティの決定方法・チーム戦・チーム戦の順位決定方法）の変更をブロックする  

### 例  
- ラウンド数：2  
- ホールインワン時のスコア変換：あり  
- ホールインワン時のスコア変換値：-2  
- パーティの最大人数：6  
- パーティの決定方法：チーム  
- チーム戦：あり  
- チーム戦の順位決定方法：平均
  
### 3.3 選手情報登録  
### 概要  
選手情報を登録する。  
**項目**  

| 項目 | 必須 | 条件 | 登録内容 |
| ------ | -- | ------------- | -------------------------------------------------------------- |
| 選手名 | ◯ |  | MAX：全角10文字、デフォルト：空白 |
| 生年月日 | ◯ |  | YYYY/MM/DD or 和暦略アルファベットYY.MM.DD  和暦略アルファベット：S（昭和）、H（平成）、R（令和） |
| チーム名 |  | チーム戦ありの場合、またはパーティの決定方法がチームの場合、必須（いずれにも該当しない場合は非表示にせず任意項目として表示する） | MAX：全角10文字、デフォルト：空白 |
| パーティ固定 | ◯ |  | チェックボックス：固定(チェックあり)、非固定(チェックなし)、デフォルト：非固定 |
| パーティ番号 |  | パーティ固定が、固定の場合 | 範囲：1〜99、デフォルト：1 |
| 不参加 |  |  | 一覧の「不参加」ボタンで切り替える（「参加に戻す」で解除）。デフォルト：参加。不参加の選手は選手情報を保存したまま、組合せ表の生成対象から除外する |
  
### 条件  
- 選手名：同一大会で重複不可（別大会では同名登録可）  
- 試合結果が1件でも登録されている選手の削除はブロックする（2.1参照）  
- 同一大会に試合結果が1件でも登録されている場合、（その選手自身に試合結果があるかどうかに関わらず）全選手のパーティ固定・パーティ番号・チーム名・不参加の変更をブロックする（組合せ表の編成に影響するため。選手名・生年月日の変更は引き続き可能）  

### 例  
- 選手名：Aさん
- 生年月日：1971/5/24  
- チーム名：スタッフ  
- パーティ固定：固定  
- パーティ番号：1  
  
### 3.4 組合せ表生成
### 概要
選手情報登録済みの全選手（不参加の選手を除く）を対象に、大会開始前に一度だけパーティ編成（組合せ表）を自動生成する。生成後は大会を通して同じ編成を使用し、ラウンドごとの再生成は行わない。
### パーティ編成ロジック
1. パーティ固定の選手は、指定された「パーティ番号」のパーティにそのまま確定で割り当てる
2. 非固定の選手は、競技情報登録の「パーティの決定方法」に従って以下のとおり割り当てる。新規パーティは、固定選手が使用していないパーティ番号から1番から順に採番する
  - **チーム**：同一チーム名の非固定選手を1チームとしてまとめ、チームを分割せずに割り当てる
    - パーティ固定の選手がいる場合：固定パーティ（パーティ番号順）ごとに、空き枠（パーティの最大人数－そのパーティの人数）に収まるチームを1チームだけ入れる（固定選手と同じチーム名のチームを優先し、なければ登録順で最初に収まるチーム）。固定パーティに入らなかったチームは、1チーム＝1パーティで新規パーティに割り当てる
    - パーティ固定の選手がいない場合：1チーム＝1パーティで新規パーティに割り当てる（複数チームを同一パーティに混在させることはしない）
    - パーティの最大人数を超えるチームがある場合は、振り分けられないためエラーとする（条件（共通）参照）
  - **シャッフル**：チーム名は考慮しない（チーム名が異なる選手も同じパーティになる）
    - パーティ数 ＝ 「全選手数（固定＋非固定）÷ パーティの最大人数」の商を切り上げた値（固定パーティ数の方が多い場合は固定パーティ数）
    - 固定パーティだけでパーティ数に足りない場合は、不足分を非固定選手による新規パーティとする
    - 非固定選手をランダムに並べ替え、その時点で人数が最も少ないパーティへ1名ずつ入れることで、各パーティの人数を平均（全選手数 ÷ パーティ数）に揃える（同数の場合は固定パーティ → パーティ番号の小さい順を優先。最大人数に達した固定パーティには追加しない）
    - 例：Aさん（チームA・パーティ1固定）、Bさん（チームB・非固定）、最大人数3の場合、2人ともパーティ1
### 開始ホールの自動割当
組合せ表生成時に、各パーティの開始ホール（1〜8）を以下の方法で自動的に割り当てる。生成後、管理者は各パーティの開始ホールを1〜8の範囲内で個別に手動で変更できる（複数パーティが同じ開始ホールになることは許容する）。ただし、同じ開始ホールのパーティにはパーティ番号の小さい順に開始グループ（1, 2, 3…）を付け、変更対象のパーティと同じ開始グループ（変更前）の他パーティに既に割り当ててある開始ホールは選択できない。
1. 1開始ホールあたりのパーティ数（商）＝ 全パーティ数 ÷ 8 の商を切り上げた値
2. 使用する開始ホール数 ＝ 全パーティ数 ÷ 1.の商 の商を切り上げた値
3. パーティ番号順に、1.の商の数ごとに区切り、開始ホール1番から順に割り当てる（全パーティ数が1.の商で割り切れない場合、最後の開始ホールのみ端数（商より少ない数）のパーティ数になる）
### 条件（共通）
- パーティの決定方法が「チーム」の場合、同一チームの選手数がパーティの最大人数を超えるときは組合せ表生成をエラーとする（エラーダイアログ文言：「チーム『○○』の人数がパーティの最大人数を超えています。選手情報またはパーティの最大人数を見直してください。」）
- パーティの決定方法が「チーム」の場合、チーム名が未入力の非固定選手が1人でもいると組合せ表生成をエラーとする（通常は3.3の必須バリデーションにより防がれるが、競技情報のパーティの決定方法を登録後に変更した場合の不整合に備える。エラーダイアログ文言：「チーム名が未入力の選手がいます。選手情報を見直してください。」）
- パーティ固定の選手が同一パーティ番号に集中し、その人数がパーティの最大人数を超える場合、組合せ表生成をエラーとする（エラーダイアログ文言：「パーティ番号○○の人数がパーティの最大人数を超えています。選手情報のパーティ番号を見直してください。」）
- 同一大会に試合結果が1件でも入力済みの場合、組合せ表自動生成（再生成）をエラーとする（エラーダイアログ文言：「試合結果が入力されています。試合結果を削除して下さい。」）。再生成する場合は、事前に試合結果を削除する必要がある
- 参加選手数（不参加の選手を除く）は2以上を必須とし、1以下の場合は組合せ表自動生成をエラーとする
- 組合せ表は、パーティ編成・開始ホールを常に一括で生成・再生成する（開始ホールのみを自動で再計算する機能は設けない。手動変更は個別に行う）
### 例
- 全24パーティの場合：商＝24÷8＝3、使用する開始ホール数＝24÷3＝8（開始ホール1〜8をそれぞれ3パーティずつ使用）
- 全21パーティの場合：商＝21÷8の商を切り上げ＝3、使用する開始ホール数＝21÷3＝7（開始ホール1〜7をそれぞれ3パーティずつ使用）
- 全20パーティの場合：商＝20÷8の商を切り上げ＝3、使用する開始ホール数＝20÷3の商を切り上げ＝7（開始ホール1〜6は3パーティずつ、開始ホール7のみ2パーティ）

### 3.5 スコア表生成
### 概要
ラウンドごとに、組合せ表のパーティ編成を用いてスコア入力欄（8ホール分）を自動生成する。組合せ表に付加する形で表示し、スコア表単独での生成・削除は行わない。
### 条件
- ラウンド数が2以上の場合、ラウンドごとに独立したスコア表を生成する（パーティ編成・開始ホールは全ラウンド共通で、ラウンドごとに変わらない）
- スコア表のホール列の表示順は、パーティの開始ホールに関わらず1番ホールから8番ホールの順（1→2→…→8）に固定する（スコア入力欄も同じ順に並べる）
- スコア表は組合せ表と同時に一括生成する（3.4参照。スコア表のみを個別に再生成する機能は設けない）

### 3.6 スコア入力、計算
### 概要
スコア表に対してホールごとの打数を入力し、ラウンド合計・総合合計を自動計算する。
### 項目
- 各ホールの打数(範囲：1〜99、デフォルト：1)
### 条件
- スコアは1ラウンド8ホール分をまとめて一括入力・保存する（ホール単位の部分保存はできない）。保存前はそのラウンドの8ホールすべてが「未入力」であり、一部のホールだけが保存された状態は発生しない（各ホールの「デフォルト：1」は保存前の入力欄の初期表示値であり、保存されるまでは記録されない。打数1（ホールインワン）と未入力を取り違えることはない）
- 本書で「試合結果が1件でも登録されている」とは、いずれかの選手の、いずれかのラウンド分のスコアが保存されている状態を指す（2.1・3.2・3.3・3.4の各ブロック条件における判定基準）
- ホールインワン（打数が1）の場合、競技情報登録の「ホールインワン時のスコア変換」が「変換あり」であれば、そのホールの打数(1)を「ホールインワン時のスコア変換値」（範囲：-5〜1、デフォルト：-2）に**置き換えて**ラウンド合計に算入する（通常打数への加算・減算のボーナスではなく、置き換えである）
- 1ラウンドの合計スコア ＝ そのラウンドの8ホール分のスコア（ホールインワン変換後）の合計
- 総合スコア ＝ 全ラウンドの合計スコアの総和（ラウンド数が1の場合は、そのラウンドの合計スコアがそのまま総合スコアとなる）
- 登録済みのスコアは修正（訂正入力）可能とする。スコアの修正は順位表に即時反映されず、最新の集計を見るには「順位表作成」を再実行する必要がある（3.7参照）
- 大会のステータスが「終了」の間は、試合結果（スコア）の入力・修正を一切行えない（2.1参照）
### 例
- 開始ホール5番のパーティの場合のホール表示順：1, 2, 3, 4, 5, 6, 7, 8（開始ホールに関わらず固定）
- ホールインワン時のスコア変換が「変換あり」、変換値が-2の場合：あるホールの打数が1（ホールインワン）→ そのホールのスコアは-2としてラウンド合計に算入する

### 3.7 順位表作成
### 概要
管理者が「順位表作成」を実行した時点のスコアをもとに集計し、総合順位表（全ラウンド合計のスコアによる順位表）を生成する（自動生成ではなく、管理者操作によるその都度の生成であり、スコア保存のたびに自動で再集計されるものではない。最新化するには再度「順位表作成」を実行する）。ラウンドごとの個別順位表は作成しない。チーム戦がある場合、チーム戦の総合順位表も作成する。
### 集計項目
- 総合スコア（全ラウンド合計）
- 年齢（生年月日と大会の開催日から算出し「◯歳◯日」で表示する。個人戦の順位表には生年月日ではなく年齢を表示する）
### 条件
- 全ラウンド分のスコアが保存済みの選手のみを集計対象とする。1ラウンドでも未保存（未入力）がある選手は、総合順位表から除外する
- 不参加の選手は総合順位表の対象外とする（集計対象外の一覧にも表示しない）
- チーム戦の場合、除外された選手はチームの合計/平均・年齢合計の算出対象からも除く。チームの全選手が除外対象となった場合、そのチーム自体をチーム戦の総合順位表から除外する
### 順位決定順序
### 個人戦
- 総合スコア（少ない方が上位）
- 生年月日(年上が上位)
- じゃんけん
### チーム戦（チーム戦ありの場合）
- 同一チームの総合スコアの合計 or 平均(チーム戦の順位決定方法)
- 同一チームの年齢の合計
- じゃんけん
### 最終順位の手動確定
- 生年月日（個人戦）・年齢の合計（チーム戦）でも決着しない場合の「じゃんけん」はシステム外（参加者同士）で行われるため、管理者がその結果を踏まえて最終順位を手動で上書き・確定できる機能を設ける
- 手動確定した順位は順位表へ直接反映するのみで、確定状態自体を記憶する仕組みは持たない。そのため、確定後に該当選手のスコアを保存（修正・削除）した状態で「順位表作成」を再実行すると、順位表はスコアから丸ごと再集計される（手動確定の内容は引き継がれない）ため、タイ条件が解消していなければ再び「じゃんけん待ち」に戻る

### 3.8 データ出力（将来対応）
Excel（.xlsx）形式でのデータ出力機能は将来対応とする（5章参照）。今回のスコープでは出力機能・出力画面は設けない。


## 4. 非機能要件  
### 対応環境  
- 対応デバイス：PCのみを想定する（レスポンシブ対応は不要）  
- 対応ブラウザ：主要モダンブラウザ（Google Chrome、Microsoft Edge、Safari）の最新版  
- 動作環境：Electronによるデスクトップアプリとして配布し、インターネット接続の有無に関わらず運営者のPC1台の上でサーバー・ブラウザが完結して動作する（LAN・他端末からの接続は想定しない）  
### 性能  
- 組合せ表生成：3秒以内  
- スコア表生成：3秒以内  
- スコア表計算：1秒以内  
- 順位表作成：3秒以内  
### セキュリティ  
- ログイン認証（管理者のみ対象。参加者はログイン不要）  
- パスワード暗号化  
- 通信はHTTP（本アプリはインターネット接続なしの単一PC環境での利用を前提とし、HTTPS化は行わない）  
- 管理者パスワードは最低8文字以上を必須とする  
- 初期管理者アカウントは環境変数（.env）でID/パスワードをシードして作成する（管理者登録用のサインアップ画面は設けない）  
- 管理者は、シードされたID・パスワードをいつでも変更できる。変更はログイン画面のダイアログから行い、未ログイン状態でも現在のID・パスワードの入力を本人確認として実行できる  
### バックアップ  
- 手動バックアップ（契機表記：「手動」）  
- ログアウト時のバックアップ（契機表記：「ログアウト」）。ログアウト操作時は「ログアウトしますか？」の確認に続けて、ログアウトする場合のみ「バックアップを作成しますか？」の確認を行い、その選択に応じてバックアップの有無を決定する（選択によらない無条件の自動バックアップは行わない）  
- バックアップ履歴から対象（作成日時）を選択して復元（リストア）できる機能。操作順は、1. バックアップデータ（作成日時）の選択、2. 復元ボタン押下、3. 復元実行最終確認（ダイアログ）とする。復元は選択したバックアップの内容で業務データ（大会情報・競技情報・選手情報・組合せ表・スコア表・順位表）を完全に上書きするため、実行前に確認ダイアログ内で注意文言を表示する。バックアップ履歴自体は復元対象に含めない（復元後も、復元時点より後に作成されたバックアップを含めすべての履歴から選択できる）  
- バックアップの保持数は20件を上限とし、超過した場合は作成日時が最も古いものから削除する  
- バックアップ履歴は作成日時の期間で絞り込んで表示できる。作成日時は秒単位まで記録・表示する  
- バックアップファイル（選手の氏名・生年月日・チーム名等の個人情報を含むJSON）はサーバー側にのみ保存し、管理者による個別ダウンロードは提供しない（復元はバックアップ履歴からの選択により行うため、ダウンロード→再アップロードという手順を必要としない）
